# 山不野智能包装质检管理平台

面向竹笋食品包装生产场景的智能质检管理系统，为工厂质检员、生产主管和系统管理员提供产线监控、模型迭代、规则配置、质量分析、诊断报告及审计追溯能力。

平台当前使用 `yolo_hrca_seg` 作为生产模型，并保留历史基线版和轻量复用版。不同模型使用统一的 mAP、FPS 等指标展示迭代差异，支持上传真实模型文件、灰度验证、生产切换、下载复用和历史版本管理。

## 主要功能

- 多产线实时监控、产品分配、异常统计和单屏/多屏切换
- 智能诊断报告生成，可下载为独立 HTML 报告
- 模型文件上传、验证、性能对比、生产切换、下载和删除
- 模型迭代指标对比，清晰展示相对基线的精度与速度变化
- 质检规则新增、编辑、启停、复制、导入、导出和发布
- 质量趋势、缺陷分布、明细查看、CSV 导出及打印
- 用户创建、角色查看、系统参数配置和操作审计
- 审计日志持久化与 CSV 导出
- 全局搜索、报警通知和统一操作反馈

## 技术架构

- 前端：React 19、TypeScript、Vite、Tailwind CSS、Recharts、Motion
- 后端：Node.js、Express、TypeScript
- 数据库：SQLite（`better-sqlite3`）
- 模型存储：本地文件仓库

## 一键运行

运行环境需要安装 Node.js 20 或更高版本。

1. 双击 `一键启动.bat`。
2. 脚本会自动清理失效状态、检查依赖、执行生产构建，并在后台启动服务；重复点击时会复用已经运行的实例，不会重复占用端口或日志文件。
3. 如果端口 `3000` 已被占用，脚本会在 `3000–3099` 范围内自动选择空闲端口。
4. 启动成功后会自动打开浏览器。
5. 使用完毕后双击 `一键关闭.bat`。

运行日志按每次启动独立保存在 `logs/server-时间戳.out.log` 和 `logs/server-时间戳.err.log`，避免日志被其他进程占用。当前端口和进程编号分别记录在 `.server.port` 与 `.server.pid`；启动和关闭操作由 `.lifecycle.lock` 防止并发执行。

## 数据与文件目录

系统首次启动时会自动创建 SQLite 数据库并初始化基础数据：

```text
data/
├── inspection.db       # 模型、规则、日志、报告和系统配置
├── models/             # 用户上传的真实模型文件
└── reports/            # 系统生成的诊断报告
```

模型上传接口单文件上限为 250 MB。前端默认支持选择 ONNX、TensorRT Engine、PyTorch 和通用二进制模型文件。

需要迁移或备份系统时，应在关闭程序后整体备份 `data/` 目录。该目录包含业务数据和上传的模型文件，不应公开提交到代码仓库。

## 默认模型迭代

| 模型 | 定位 | mAP | FPS | 默认状态 |
| --- | --- | ---: | ---: | --- |
| `yolo_hrca_seg_baseline` | 初始分割基线，用于回归对照 | 94.1% | 118 | 已归档 |
| `yolo_hrca_seg_lite` | 面向边缘设备的轻量复用版 | 96.5% | 182 | 灰度测试 |
| `yolo_hrca_seg` | 融合 HRCA 的当前生产模型 | 98.2% | 145 | 生产中 |

以上内置条目提供可复用的模型元数据清单。用户实际上传的模型文件会保存到 `data/models/`，并可从模型管理页面原样下载。

## 项目结构

```text
├── src/
│   ├── components/     # 布局、通知、弹窗和产线动画
│   ├── lib/            # 前端 API 与下载工具
│   └── pages/          # 监控、规则、模型、统计和系统页面
├── server.ts           # Express API、SQLite 数据层和静态服务
├── PRODUCT.md          # 产品用户、目标和设计原则
├── 一键启动.bat
└── 一键关闭.bat
```

## 注意事项

- 本项目当前面向本地或受信任内网环境，尚未接入企业统一身份认证。
- 诊断报告用于辅助生产判断，最终处置仍应结合现场设备点检结果。
- 若启动失败，请查看启动窗口显示的日志路径，或打开 `logs/` 中时间最新的 `.err.log`；依赖或构建错误会同时显示在启动窗口中。
